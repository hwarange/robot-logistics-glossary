🧭 AI 담당을 위한 가이드

6인 팀 로봇 물류 시뮬레이션 프로젝트에서 AI 담당이 무엇을 만들고, 무엇을 어떤 순서로 공부하면 되는지 정리했습니다.

1. AI 담당이 이 프로젝트에서 만드는 것

로봇·시뮬레이션 팀이 Isaac Sim에서 "움직이는 로봇과 물류센터"를 만든다면, AI 담당은 그 위에서 도는 두뇌를 만듭니다. 대표적으로 네 가지입니다.

  • 작업 할당 (Task Allocation) — 새 주문이 들어오면 어느 로봇에게 맡길지 결정. 가장 먼저 만들 수 있고 효과가 눈에 보이는 부분입니다. 규칙 기반(가장 가까운 로봇) → 경매 기반 → OR-Tools 최적화 순으로 발전시키기 좋습니다.
  • 다중 로봇 경로 (MAPF) — 수십 대 로봇이 서로 충돌·교착 없이 다니게 하기. A* → 우선순위 계획(Prioritized Planning) → CBS 순으로 구현 난이도가 올라갑니다.
  • 강화학습 정책 (RL) — Isaac Lab으로 로봇 제어·회피 정책을 학습. 화려하지만 난이도와 시간 비용이 커서, 위 두 개가 돌아간 뒤에 도전하는 걸 추천합니다.
  • 평가 지표 설계 — 시간당 처리 주문 수(Throughput), 주문 평균 대기시간, 로봇 가동률, 충돌·교착 횟수. 어떤 AI를 넣든 이 지표로 전/후를 비교해야 "AI가 개선했다"를 증명할 수 있습니다.

2. 추천 학습 순서 (로드맵)

  1. 도메인 용어 — 이 사이트의 물류센터 · 물류 로봇 카테고리부터. GTP, 피킹, WMS/WCS 정도는 팀 회의에서 바로 나옵니다.
  2. 경로 탐색 — A*를 직접 구현해보고(격자 맵, 100줄 내외), MAPF·CBS 개념을 이해합니다. 물류 로봇 AI의 핵심입니다.
  3. 최적화 기초 — Google OR-Tools의 CP-SAT으로 "로봇 5대 × 작업 20개" 할당 문제를 풀어봅니다. RL보다 빠르고 확실합니다.
  4. RL 기초 — 강화학습 개념(보상, 정책, PPO)을 잡고 stable-baselines3로 간단한 환경을 학습시켜본 뒤 Isaac Lab 튜토리얼로 넘어갑니다.
  5. MARL·최신 모델(VLA 등) — 필요해질 때 공부해도 늦지 않습니다. 발표 때 트렌드로 언급하는 용도로는 최신 로봇 AI 카테고리를 훑어두세요.

3. 도구 스택 추천

  • Python — 모든 것의 기본. 시뮬레이션 제어(Isaac Sim Python API)도 Python입니다.
  • Google OR-Tools (CP-SAT) — 작업 할당·스케줄링. 무료, 문서 좋음, 결과가 결정적이라 디버깅이 쉽습니다.
  • stable-baselines3 — RL 개념 연습용. PPO 한 줄 학습으로 감을 잡기 좋습니다.
  • Isaac Lab — GPU 병렬 환경에서 로봇 RL 학습. 프로젝트의 본 학습 도구입니다.
  • SimPy (선택) — 물리 없이 "시간당 처리량" 같은 운영 실험만 빠르게 돌리는 이산사건 시뮬레이션(DES). 물류 최적화 실험에 의외로 유용합니다.

4. GPU 환경 전략

  • 로컬 (RTX 4070 8GB 노트북) — Isaac Sim 씬 편집, 로봇 1~2대 소규모 테스트, 코드 개발까지. VRAM 8GB는 Isaac Sim 최소 사양 수준이라 대규모 씬·학습은 무리입니다.
  • 원격 서버 (L40S ×4, Linux) — Isaac Lab 병렬 RL 학습, 대규모(수십 대 로봇) 시뮬레이션, 합성 데이터 생성은 여기서. 헤드리스(headless) 모드 + 스트리밍으로 돌리는 법을 초반에 익혀두면 개발 사이클이 빨라집니다.

5. 팀 협업 인터페이스

AI 담당의 결과물은 결국 로봇/시뮬 팀 코드와 만나야 합니다. 초반에 이것부터 합의하세요.

  • 인터페이스 계약 — "AI 모듈은 무엇을 입력받고(로봇 위치, 주문 목록) 무엇을 출력하는가(로봇별 목적지)"를 문서로 고정. ROS 2를 쓴다면 토픽/서비스 이름과 메시지 형식까지.
  • 시뮬레이션과 분리된 개발 — Isaac Sim 없이도 AI 로직을 테스트할 수 있게 간단한 2D 격자 시뮬레이터(Python)를 직접 만들어두면, 팀 통합 전에 알고리즘을 빠르게 검증할 수 있습니다.
  • 시나리오 고정 — 성능 비교는 같은 주문 시퀀스·같은 랜덤 시드에서. 아니면 "개선됐다/아니다"를 말할 수 없습니다.

6. 흔한 함정 (미리 알면 몇 주 아낍니다)

  • 처음부터 MARL 금지 — 다중 로봇이라고 바로 멀티에이전트 강화학습으로 가면 대부분 수렴하지 않습니다. 중앙집중식 할당 + 고전 경로계획이 훨씬 잘 동작하고, RL은 그 다음입니다.
  • RL은 보상 설계가 80% — 알고리즘 교체보다 보상 함수·관측 설계를 다듬는 게 거의 항상 더 효과적입니다.
  • 격자 추상화의 힘 — 경로·할당 문제는 연속 공간이 아니라 격자/그래프로 추상화해서 푸는 게 정석입니다. Isaac Sim의 연속 세계와는 "격자 경로 → 웨이포인트 추종"으로 연결합니다.
  • 데모가 목표 — 6인 학기 프로젝트의 최종 산출물은 논문이 아니라 시연입니다. "로봇 10대가 주문 100건을 처리하는데 AI 할당으로 처리량 30% 향상" 같은 한 문장을 목표로 역산하세요.

각 용어의 정의는 카드에 표기된 출처(공식 문서 · 위키피디아 · 논문)를 기반으로 정리했습니다.
